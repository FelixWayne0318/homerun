## 二、复核纠正：842 秒"长事务"是误报

上一轮把 `Long transaction held 842.49s origin=...start_loop tables=weather_snapshot` 判为"整周期包在一个 session、跨慢 await 持有事务"，这个判断**是错的**，已实测推翻：

| 验证 | 方法 | 结果 |
|---|---|---|
| 连接是否真被释放 | `/tmp/probe_release.py`：在 `release_conn` 内 `sleep(40)`，12 秒后查 `pg_stat_activity` | 0 行 `idle in transaction` → 连接确实归还连接池 |
| 是否存在长事务 | 天气周期运行期间查 `pg_stat_activity` 的 `xact_start` | 全库只有 0.8s 级事务，无 800s 级事务 |
| 埋点为何报 842s | `backend/models/database.py` | `after_begin` 仅在 `_slow_tx_started_at is None` 时打戳，`before_commit` 只读不清 → 长寿命 Session 量到的是**session 寿命** |

修复：新增 `after_commit` / `after_rollback` 监听，事务结束即清除时间戳与 origin。验证脚本 `/tmp/probe_tx_stamp.py` 输出 `first_stamp True, cleared_after_commit True, second_is_new True`。天气/新闻编排器的 `release_conn` 边界**不需要重构**，未改动其事务结构。

## 六、剩余风险与未决项

1. **16 个 scanner 策略仍无 trader 消费**（scanner pending 3795、weather pending 50）：`source_configs` 设计上每 trader 恰好一条，交易单位是 trader，这是产品配置而非缺陷。**2026-11-09 操作者决定：暂不建 trader**，维持现状。
2. **news 平面的 LLM 费用**：**2026-11-09 操作者决定"暂时不付费"，已执行 `launchctl bootout gui/501/com.homerun.worker-news`**。平面进程已退出，`worker_snapshot.news` 标记 `running=false`（"新闻平面已由操作者停用（暂不支付 LLM 费用）"），最后一条 LLM 调用时间为 10:37:01，之后 10 分钟内无新增调用。plist 保留在 `~/Library/LaunchAgents/`，需要恢复时执行 `launchctl bootstrap gui/501 ~/Library/LaunchAgents/com.homerun.worker-news.plist`；其它平面不受影响。
3. **保留策略与容量**：决策 30 天保留对应稳态约 30GB 量级（当前 1.4GB/30 小时推算）。若磁盘吃紧，把 `cleanup_trader_decisions_days` 降到 7 天即可，属配置项。
4. **内存余量**：16GB 机器上三平面 + torch 常驻，free 常年低于 1GB（压缩内存兜底），建议观察 `worker_*_err.log` 中的 jetsam 记录。
5. **实盘准入**：无凭证，live 保持禁用即为设计预期；实盘前需另做凭证配置 + 小额穿仓验证，不在本次范围。
6. **全量测试**：单进程全量会被上游测试间状态污染卡住（已核实与本批改动无关）。上线门禁采用"逐文件隔离跑 + 核心 65 项"的口径。

## 七、回滚路径

- 代码：`git revert <本次提交>`，重启 `com.homerun.backend` 与 `com.homerun.worker-trading`。
- 自动清理：`update app_settings set auto_cleanup_enabled = false;` 后重启后端。
- 轮转/备份：`launchctl bootout gui/501/com.homerun.logrotate`、`...dbbackup`，脚本文件保留不影响运行。
- 数据恢复：`pg_restore -d postgresql://homerun:homerun@127.0.0.1:5432/homerun data/backups/homerun-<时间戳>.dump`（先确认目标库为空或按表恢复）。
