## 二、Polymarket 网络：根因与当前处置

### 根因

- 系统 resolver：`198.18.0.2`（utun6）
- `clob.polymarket.com` → `198.18.206.184`
- `gamma-api.polymarket.com` → `198.18.206.177`
- `data-api.polymarket.com` → `198.18.206.179`

同一时刻有些 Polymarket 端点 200、有些 8 秒超时，正是 fake-ip 抢答导致。用 Cloudflare DoH 取到的真实 IP 已实测可连：

- clob / data-api / polymarket.com：`172.64.153.51`
- gamma-api：`54.239.180.50`

`curl --resolve` 验证：

- clob → 172.64.153.51：404 / 0.67s（404 是 token_id=0 的正常语义）
- gamma → 54.239.180.50：200 / 0.54s

### 已尝试但无效的修复

已在 `dns_config.yaml`、活动 profile `LSYHy8xfAbk9.yaml`、`clash-verge.yaml` 中加入 `+.polymarket.com` / `*.polymarket.com` / `polymarket.com` 的 fake-ip-filter，并重启 Clash Verge 两次。运行时 `clash-verge.yaml` 确实生成了 filter，但：


说明该 fake-ip 由 TUN 网卡层接管，当前 Clash Verge 版本没有把该 filter 应用到系统解析；应用日志还有 `set system dns failed: exit code 1`。**本次已把这些无效的配置改动还原，避免留下误导性配置。**

## 三、回测功能复测

### 根因

未限定数据范围的回测（Backtest Studio 的 Auto 模式只发 start/end）会落到“live ingestor universe”，然后去读全量历史 parquet 事件流；工作线程卡在 `services/recorded_event_bus/storage/parquet_backend.py:576 _read_file_rows` 的 `json.decoder.raw_decode`。这不是 DB 锁，也不是引擎算不动，所以 UI 上 progress 恒 0、`snapshots_processed` 恒 0。

### 决定性对照

用 `provider_dataset_ids=["polybacktest:f662df0204314654"]` + `start=2026-11-08T03:06:13Z` / `end=2026-11-08T03:09:59Z`、`slug=basic`、`seed=42`、`initial_capital_usd=1000`：

- 同步 `/api/backtest/run`：**2.52s**，`n_snapshots=4146`，`trade_count=0`，`total_return_pct=0.0`（`a04368892da1408a`）
- 队列 `/api/backtest/runs/enqueue`：`queued → running(Worker claimed run) → completed | Done · trades=0 · return=0.00% · 2.5s`；回读 `/runs/{id}` 得 `n_snapshots=4146`（`9423adbb785d4fd0`）
- 修复后再次验证：`3373922a414a4038` 的 `/status` 最终 `completed`、`snapshots_processed=4146`

### 正确用法

1. 回测工作室顶部策略选择 **Basic Arbitrage**。
2. `DATA SOURCE` 必须选 **Datasets**，勾选一个带 `PARQUET` 的数据集（例如 `BTC · 4,164 snaps · 2 tokens`）。
3. 不要用 **Auto**（Auto 只发滚动 start/end，会去读 live ingestor 全量历史）。
4. 点 `Continue to Run` → `Run`；完成后 `Inspect` 的 `n_snapshots > 0` 才说明有回放数据。

`trade_count=0` 表示该策略在该窗口没有触发，不等于回测故障；`n_snapshots=0` 才表示窗口没有录制数据。
