## 1. 这个系统是做什么的

一句话：**Homerun 是一个预测市场（Polymarket、Kalshi）的自动扫描 + 策略计算 + 模拟/实盘交易系统。**

它每 30～60 秒做一轮事情：

1. 从 Polymarket 等平台拉取市场、订单簿、价格；
2. 用 30 个策略计算有没有“定价错误”或“套利机会”；
3. 把机会写进数据库，显示在“机会”页面；
4. 交易员（Bot）按配置决定要不要下单；
5. 下单先走影子模式或沙盒账户，不碰真钱；
6. 你在界面上看机会、持仓、盈亏，决定是否上线实盘。

它**能**做的事：

- 自动扫描几千个预测市场；
- 计算 YES+NO 套利、跨市场价差、结算滞后、天气/新闻/加密等策略；
- 用沙盒账户模拟买卖、结算、算盈亏；
- 用历史快照做回测；
- 在影子模式下验证交易员逻辑，不花真钱。

它**暂时不能**做的事（截至 2026-11-09）：

- 不能在没有 Polymarket 私钥的情况下做实盘下单；
- 默认 1 天窗口的回测会卡死，只能用短窗口；
- 机会卡片上没有“直接买进某个沙盒账户”的按钮，只能用交易员的买入按钮或 API；
- 模拟账户没有撤单功能（模拟是即时成交，没有挂单可撤）。

## 2. 小白必须先懂的 12 个词

| 词 | 大白话解释 |
| --- | --- |
| 市场（Market） | 一个可以下注的问题，比如“某地会不会下雨”。 |
| YES / NO | 同一个问题的两个方向。YES 价格 0.6，表示市场认为有 60% 概率发生。 |
| 机会（Opportunity） | 系统算出来“价格不合理、可能有利润”的一组下注。 |
| 策略（Strategy） | 一套判断规则，负责发现机会。系统内置 30 个。 |
| 扫描器（Scanner） | 定时把所有市场拉一遍、喂给策略的程序。 |
| 交易员 / 机器人（Trader / Bot） | 真正决定“这个策略信号要不要下单、下多少”的执行单元。 |
| 影子模式（Shadow） | 只记账、不真下单。用来验证交易员逻辑。 |
| 沙盒账户（Sandbox） | 用虚拟资金模拟买卖的账户，和真钱完全隔离。 |
| 实盘（Live） | 真钱、真下单。需要私钥、授权、风控。 |
| 敞口（Exposure） | 当前押了多少钱在市场里。 |
| ROI | 回报率，利润 ÷ 成本。 |
| 回测（Backtest） | 用历史数据重放一遍，看策略过去会不会赚钱。 |

**方式 A：双击启动（最简单）**

**方式 C：手动检查并补启动**


健康标准：

| 检查 | 正常值 |
| --- | --- |
| `/health` | `200` |

| 前端 | `200` |
| 顶部滚动条 | 显示“10/11 · 1 警告”或类似 |

### 3.3 打开界面

浏览器访问：

```
http://127.0.0.1:3000
```

第一次打开如果页面空白，等 5～10 秒；后端要加载市场缓存。

## 5. 第一次上手：30 分钟走完一遍

### 第 1 步：确认账户

打开“账户”标签，看顶部账户选择器：

- 如果显示“未选择账户”，点开下拉，选择一个沙盒账户；
- 如果没有沙盒账户，点“沙盒交易台”，再点“新建沙盒账户”。

### 第 2 步：创建一个沙盒账户

路径：**账户 → 沙盒交易台 → 新建**

填写：

| 字段 | 建议值 |
| --- | --- |
| 账户名称 | 沙盒测试1（或你自己的名字） |
| 初始资金 | 10000 |
| 单仓上限 | 10% |
| 最大持仓数 | 10 |

点“创建”。创建后你会看到：

- 模拟资产约 $10,000；
- 模拟盈亏 $0；
- 模拟持仓 0。

### 第 3 步：看机会

打开“机会”标签，默认在市场子标签。

你会看到一张张机会卡片，重点看：

- 标题：哪个市场；
- 策略：哪个策略发现的；
- 成本 / 预期回报 / ROI；
- 风险分。

如果卡片太多，用顶部搜索框或筛选器。

### 第 4 步：创建一个交易员（机器人）

路径：**机器人 → 新建 / 从模板创建**

建议第一次选模板：

- `Crypto Full-Stack Trader`：加密市场做市；
- 或任意一个 `Shadow` 模式模板。

关键设置：

| 设置 | 建议 |
| --- | --- |
| 模式 | `shadow`（影子） |
| 状态 | 启用 |
| 策略 | 先只选 1 个 |
| 单笔金额 | $10 以内 |

保存后，交易员会出现在列表里，状态为“运行中”。

### 第 5 步：启用策略

路径：**策略 → 策略**

找到你要用的策略（例如 `basic`、`stat_arb`、`weather_distribution`），确认：

- 状态是 `loaded`；
- 开关是启用；
- 没有红色错误信息。

### 第 6 步：等第一轮扫描

扫描器是自动的，不需要点“开始”。等 30～60 秒，回到“机会”页刷新。

正常现象：

- 机会数量从 0 变成几十条；
- 顶部扫描器状态显示 running；
- 子标签计数逐步出现。

如果一直是 0，先看第 11 节“常见故障”。

## 6. 日常使用：看机会、买入、看持仓、看业绩

### 6.1 看机会的三种视图

| 视图 | 适合谁 | 有没有买入按钮 |
| --- | --- | --- |
| 卡片 | 快速浏览 | 卡片本身通常没有 |
| 列表 | 对比多个机会 | 有“买入”按钮 |
| 终端 | 看深度、下单 | 有“买入”按钮 |

所以如果你在卡片上找不到买入按钮，切到“列表”或“终端”。

### 6.2 买入是怎么走的

界面上的“买入”按钮调用的是：

```
POST /api/traders/{trader_id}/manual-buy
```

它会：

1. 让你选一个交易员；
2. 按交易员当前模式处理：
   - `shadow`：只写影子订单，不花钱；
   - `live`：走真实下单（当前未配置私钥，会失败）。
3. 写入该交易员的订单和持仓。

**注意：它不是直接买进“沙盒账户”。** 沙盒账户的下单接口是另一个：

```
POST /api/simulation/accounts/{account_id}/execute
```

这个接口目前没有界面按钮，只能用 API 调用（见第 7 节）。

### 6.3 看持仓

路径：**持仓**

- 顶部可切换“全部 / 沙盒 / 实盘”；
- 可以按账户、场所、方向、规模筛选；
- 每行显示成本、未实现盈亏、敞口、标价。

注意：顶部滚动条的“敞口”是**实盘编排器**的口径，不包含沙盒持仓。所以会出现“持仓 5 条、敞口 $0.00”，这不是数据错误，是口径不同。

### 6.4 看业绩

路径：**业绩**

三个子标签：

- 概览：已实现盈亏、ROI、胜率、回撤；
- 洞察：最佳/最差交易、ROI 中位数、策略表现；
- 历史：逐笔交易。

新手只看两个数：

- **已实现盈亏**：已经结算的赚亏；
- **ROI**：赚亏相对投入的比例。

## 7. 沙盒账户完整实操

> 这一节是“真按步骤做一遍”的版本。全部是虚拟资金，不会动真钱。

### 7.1 先查账户和余额

```bash
curl -s http://127.0.0.1:8000/api/simulation/accounts | python3 -m json.tool
```

记下你的账户 `id`，例如：

```
fe35cca1-dd76-49e1-b1d2-2f816f65e9cf
```

### 7.2 找一条可下单的机会

```bash
curl -s "http://127.0.0.1:8000/api/opportunities?limit=1" | python3 -m json.tool | head -40
```

记下 `id` 和 `positions_to_take` 里的 `token_id`、`outcome`、`price`。

### 7.3 下单（买 10 份）

把下面的 `ACCOUNT_ID` 和 `OPPORTUNITY_ID` 换成你自己的：

```bash
ACCOUNT_ID="fe35cca1-dd76-49e1-b1d2-2f816f65e9cf"
OPPORTUNITY_ID="把机会 id 填这里"

curl -s -X POST "http://127.0.0.1:8000/api/simulation/accounts/$ACCOUNT_ID/execute" \
  -H 'Content-Type: application/json' \
  -d "{\"opportunity_id\":\"$OPPORTUNITY_ID\",\"position_size\":10}" | python3 -m json.tool
```

返回里重点看：

- `status`：`executed`；
- `trade_id`：这笔成交的编号；
- `total_cost`：扣了多少钱；
- `expected_profit`：预期利润。

### 7.4 看持仓

```bash
curl -s "http://127.0.0.1:8000/api/simulation/accounts/$ACCOUNT_ID/positions" | python3 -m json.tool
```

### 7.5 结算（模拟开奖）

```bash
TRADE_ID="上一步返回的 trade_id"

curl -s -X POST "http://127.0.0.1:8000/api/simulation/trades/$TRADE_ID/resolve?winning_outcome=NO" | python3 -m json.tool
```

返回：

- `resolved_win` 或 `resolved_loss`；
- `actual_payout`：赔付；
- `actual_pnl`：这笔盈亏。

结算后回“账户/沙盒交易台”刷新，应该看到余额和盈亏变化。

### 7.6 这个流程里没有“撤单”

模拟账本是**即时成交**模型：

- 没有挂单，所以没有可撤的单；
- 下单后直接变成持仓；
- 想“反悔”只能结算或删除账户重建。

实盘侧倒是有撤单接口：

```
DELETE /api/trader-orchestrator/live/orders/{order_id}
DELETE /api/trader-orchestrator/live/orders
```

但当前没有实盘凭证，暂时用不上。

## 8. 回测怎么用（含避坑）

### 8.1 界面入口

路径：**策略 → 研究 → 回测工作室 → 左侧 Setup / PICK DATA**

界面有三档数据源：

- `Auto / ROLLING WINDOW`：按当前时间往前推 N 天；
- `Recording session / CAPTURED WINDOW`：已录制的窗口；
- `Datasets / MULTI-SELECT VENDOR DATA`：导入的数据集。

### 8.2 关键避坑

**不要用默认的 1 天窗口。** 当前实现会把整段数据一次性读进内存，1 天全市场会卡死，表现为：

- 状态一直 `Worker claimed run`；
- 进度 0%；
- 点取消返回成功，但任务还在跑；
- 只能重启 jobs worker 才能恢复。

已验证可用的窗口：

- 2026-11-08 03:00–03:10（10 分钟）；
- 约 4164 条快照；
- 通常 2～20 秒完成。

### 8.3 用 API 跑一个安全的短窗口

```bash
cd /Users/ahs/Projects/homerun

SLUG=basic
START=2026-11-08T03:00:00+00:00
END=2026-11-08T03:10:00+00:00

data/Postgres.app/Contents/Versions/16/bin/psql \
  "postgresql://homerun:homerun@127.0.0.1:5432/homerun" -t -A \
  -c "select source_code from strategies where slug='$SLUG';" > /tmp/bt_src.py

python3 - "$SLUG" "$START" "$END" <<'PY'
import json, sys, time, urllib.request
slug, start, end = sys.argv[1:4]
payload = {
    "source_code": open('/tmp/bt_src.py').read(), "slug": slug,
    "start": start, "end": end,
    "initial_capital_usd": 1000.0,
    "discovery_sample_interval_seconds": 5.0,
    "discovery_max_ticks": 5000, "seed": 42,
}
req = urllib.request.Request(
    "http://127.0.0.1:8000/api/backtest/runs/enqueue",
    data=json.dumps(payload).encode(),
    headers={"Content-Type": "application/json"},
)
rid = json.load(urllib.request.urlopen(req))["run_id"]
print("run_id:", rid)
for _ in range(40):
    time.sleep(3)
    st = json.load(urllib.request.urlopen(f"http://127.0.0.1:8000/api/backtest/runs/{rid}/status"))
    print(st["status"], "|", st["message"])
    if st["status"] in ("completed", "failed", "cancelled"):
        break
d = json.load(urllib.request.urlopen(f"http://127.0.0.1:8000/api/backtest/runs/{rid}"))
e = d.get("execution") or {}
print("trades =", e.get("trade_count"), "snapshots =", e.get("n_snapshots"), "return% =", e.get("total_return_pct"))
PY
```

### 8.4 怎么看结果

| 结果 | 含义 |
| --- | --- |
| `completed` + `snapshots > 0` | 回测正常 |
| `completed` + `trades = 0` | 正常，策略在该窗口没触发 |
| `snapshots = 0` | 该窗口没数据，换窗口 |
| 长时间 `running`、0% | 数据量过大卡住，需要清理 |

## 9. 新闻、天气、AI、数据、发现这几个模块

| 模块 | 现在能不能用 | 说明 |
| --- | --- | --- |
| 新闻 | 停用（省钱） | 新闻 worker 主动停止，不调用 LLM，不产生费用 |
| 天气 | 依赖 news 平面 | 天气 worker 和 news 在同一个进程中；news 进程停掉后天气也会停 |
| AI | 部分可用 | 接口正常，但完整“判定→落库”流程未全量验证 |
| 数据 | 只读可用 | 数据集浏览、质量、存储统计正常；录制会话当前为空 |
| 发现/追踪 | 只读可用 | discovery worker 在跑，但积压较多，未逐条验证 |
| 实盘 | 不可用 | 缺 Polymarket 私钥，`initialized=false` |

## 10. 风控与紧急停止

### 10.1 先认识三个开关

| 开关 | 作用 | 在哪 |
| --- | --- | --- |
| Kill Switch | 一键阻止新订单 | 交易员/编排器页面 |
| Pause All | 暂停所有 worker | Worker 状态/设置 |
| Emergency Stop | 实盘紧急停止 | 实盘交易台 |

### 10.2 新手建议

- 始终让交易员处于 `shadow`；
- 单笔金额不超过 $10；
- 不要打开 `live` 模式，除非私钥、授权、风控都配好；
- 每天看一次“业绩”和“持仓”，确认没有异常单。

### 10.3 暂停一切

```bash
curl -s -X POST http://127.0.0.1:8000/api/workers/pause-all | python3 -m json.tool
```

恢复：

```bash
curl -s -X POST http://127.0.0.1:8000/api/workers/resume-all | python3 -m json.tool
```

## 11. 常见故障与处理

| 现象 | 可能原因 | 怎么处理 |
| --- | --- | --- |
| 页面打不开 | 前端进程没起 | `launchctl list | grep homerun`，补 `com.homerun.frontend` |
| `/health` 不是 200 | 后端进程挂了 | `launchctl kickstart -k gui/501/com.homerun.backend` |
| 机会一直是 0 | 扫描器首轮未完成/加载态 | 等 60 秒刷新；仍为 0 查 worker 状态 |
| 机会子标签显示 0，但总数不是 0 | REST 还没返回 | 等页面加载完，不是故障 |
| 顶部显示 1 警告 | news 停用 | 正常，新闻是主动停的 |
| 天气不更新 | news 平面停了，天气跟着停 | 见下方“恢复天气” |
| 持仓 5 条但敞口 $0.00 | 沙盒持仓不计入实盘敞口 | 口径差异，不是错 |
| 回测卡在 claimed | 数据量超过内存包线 | 取消任务、重启 jobs worker，改用短窗口 |
| 实盘按钮报未初始化 | 缺私钥/凭证 | 正常降级，不要反复点 |
| 日志大量 ERROR | 数据库重启/外键冲突 | 先看当前是否复现，历史错误不代表现在有问题 |

### 恢复天气（不产生 LLM 费用）

天气 worker 和新闻 worker 共用一个 `news` 进程。要让天气恢复，按顺序执行：

**第 1 步：关掉新闻主开关（防止启动后调用 LLM）**

```bash
curl -s -X POST "http://127.0.0.1:8000/api/workers/news/enable?enabled=false" | python3 -m json.tool
```

确认返回里 `enabled` 为 `false`。

**第 2 步：打开天气主开关**

```bash
curl -s -X POST "http://127.0.0.1:8000/api/workers/weather/enable?enabled=true" | python3 -m json.tool
```

**第 3 步：启动 news 平面（天气跟着它一起跑）**

先检查它是否已经注册：

```bash
launchctl print gui/501/com.homerun.worker-news >/dev/null 2>&1; echo $?
```

- 返回 `0`：已注册，执行 `launchctl kickstart -k gui/501/com.homerun.worker-news`；
- 返回 `113`：未注册，执行：

```bash
launchctl bootstrap gui/501 ~/Library/LaunchAgents/com.homerun.worker-news.plist
```

**第 4 步：确认天气在跑**

```bash
curl -s http://127.0.0.1:8000/api/weather-workflow/status | python3 -m json.tool
```

看 `last_scan` 是否在最近几分钟内更新。新闻开关为 `false` 时，新闻循环空转，不调用 LLM，不产生费用。

## 14. 常见问题 FAQ

**Q1：为什么机会卡片上没有“买入”按钮？**
卡片视图通常没有；切到“列表”或“终端”。买入走交易员的手动买入接口，不是直接买沙盒账户。

**Q2：为什么我买了之后沙盒账户余额没变？**
因为你用的是交易员的影子下单，账记在交易员订单里，不进沙盒账户。要动沙盒账户，用第 7 节的 `execute` 接口。

**Q3：为什么持仓有 5 条，顶部敞口是 $0.00？**
顶部敞口取实盘编排器口径，沙盒持仓不计入。不是数据错误。

**Q4：为什么回测一直不动？**
默认 1 天窗口超出内存包线。改用 10 分钟窗口，或等准入护栏补上。

**Q5：新闻为什么是停的？**
你要求暂不支付 LLM 费用，所以主动停用。天气会受影响，需要按第 11 节恢复。

**Q6：能不能直接做实盘？**
当前不能。缺 Polymarket 私钥，实盘服务 `initialized=false`。配置完整凭证后还要先做最小金额验证。

**Q7：数据会不会丢？**
数据库有每日备份、日志轮转；但沙盒账户是测试账本，不建议存重要数据。
