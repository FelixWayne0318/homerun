# Homerun 使用教程（小白网页版 · Polymarket 单平台）

> 适用对象：第一次接触本项目、没有量化交易经验、也不想碰命令行的人。
> 适用环境：本机 macOS，项目目录 `/Users/ahs/Projects/homerun`，系统网页 `http://127.0.0.1:3000`。
> **当前部署模式：Polymarket 单平台。** Kalshi 跨平台策略已主动停用；这不是故障，也不是“暂时没加载”，而是当前上线口径。
> 本教程原则：**所有操作都在系统网页里点按钮完成；不需要输入任何命令。**
> 交易原则：**先沙盒、后实盘；先小额、后放大。** 当前实盘未配置凭证，教程中的“买入”默认只走影子/沙盒，不会动真钱。

**开始前请先记住五条：**

1. **网页能打开、右上角状态点不是红色，就是基本正常。** 不需要看接口、日志或数据库。
2. **顶部 `工作器 10/11 · 1 警告` 不是故障。** 少的那 1 个是设计内关闭的新闻（省钱），不是 worker 崩了。
3. **当前只有 Polymarket 机会；找不到 Kalshi、跨平台策略或 `cross_platform` 卡片是正常的。** 不要为了把它“修回来”去改策略开关或代理设置。
4. **回测不要选 `Auto`。** 要选 `Datasets`，并勾选带 `PARQUET` 的明确数据集；否则可能一直 0%。
5. **沙盒是即时成交，不是挂单撮合。** 下单后直接成为持仓，没有“挂单→撤单”这个动作；网页也没有“手动结算”按钮。

> 窗口较窄（约 842 像素）时，顶部账户数值会自动隐藏，只保留账户名、搜索框、`Worker and VPN status`、主题按钮和 `Pause`；这是响应式布局，不是数据丢失。要看账户数值，去 `账户` 或 `业绩` 页。

## 1. 这个系统是做什么的

一句话：**Homerun 是一个预测市场自动扫描 + 策略计算 + 模拟/实盘交易系统。当前部署只接 Polymarket，Kalshi 跨平台已主动停用。**

它每 30～60 秒做一轮事情：

1. 从 Polymarket 拉取市场、订单簿、价格；
2. 用当前加载的策略计算有没有“定价错误”或“套利机会”；
3. 把机会写进数据库，显示在“机会”页面；
4. 交易员（机器人）按配置决定要不要下单；
5. 下单先走影子模式或沙盒账户，不碰真钱；
6. 你在网页里看机会、持仓、盈亏，决定是否上线实盘。

### 1.1 它能做的事

- 自动扫描几千个 Polymarket 预测市场；
- 计算 YES+NO 套利、结算滞后、统计套利、做市、尾部持有、新闻动量、闪崩反转等策略；
- 用沙盒账户模拟买卖、结算、算盈亏；
- 用历史快照做回测；
- 在影子模式下验证交易员逻辑，不花真钱。

### 1.2 当前能力边界（2026-11-12 实况）

这一节很重要。**下面这些事情当前没有开放，不要硬找，也不要用代码去补。**

| 能力 | 当前真实情况 |
| --- | --- |
| Polymarket 行情/机会 | 正常。扫描器、订单簿、机会池都在跑。 |
| Kalshi 行情/跨平台套利 | **不可用，且已主动停用。** `cross_platform` 策略处于 `enabled=false`；不要再让它每轮去请求 Kalshi、吃超时。 |
| Kalshi 实盘账户 | 未配置凭证；即使入口可见也不可用。当前上线口径不包含 Kalshi。 |
| 实盘下单 | 不能。缺少 Polymarket 私钥/凭证，实盘服务未初始化；看到“未初始化”是正常降级。 |
| 直接对某个沙盒账户下单 | 当前没有“账户下单”按钮。`机会 → 交易员` 的 `买入` 走的是交易员手动买入，不是直接扣沙盒账户。 |
| 新建机器人 | 当前 `机器人` 页未发现“新建机器人”入口；请使用页面已有的影子机器人。 |
| 手动结算沙盒交易 | 没有“结算”按钮。沙盒账本按市场结果和后台流程更新。 |
| 沙盒撤单 | 不支持。沙盒是即时成交模型，没有挂单。 |
| 后台进程彻底挂了 | 网页不能重启后台。只能在 Finder 里双击启动器；再不行找维护者。 |
| 回测导出 PDF | 当前本机缺依赖，点下载会失败；回测结果本身仍可看。 |
| 新闻长期主开关 | 网页的“暂停”只暂停当前工作流；长期主开关当前没有独立网页入口。保持现状即可。 |
| 实盘凭证配置 | 网页不提供私钥录入；需要维护者在部署层配置。 |

> **一句话原则：** 现在看到 `cross_platform` 消失、Kalshi 搜索没有结果、策略数不是 30，都是单平台模式的正常表现；不要把它当成需要“修复”的故障。

## 2. 小白必须先懂的 13 个词

| 词 | 大白话解释 |
| --- | --- |
| 市场（Market） | 一个可以下注的问题，比如“某地会不会下雨”。 |
| YES / NO | 同一个问题的两个方向。YES 价格 0.6，表示市场认为有 60% 概率发生。 |
| 机会（Opportunity） | 系统算出来“价格不合理、可能有利润”的一组下注。 |
| 策略（Strategy） | 一套判断规则，负责发现机会。系统内置约 30 个，当前单平台模式实际加载 29 个（`cross_platform` 已停用）。 |
| 扫描器（Scanner） | 定时把所有市场拉一遍、喂给策略的程序。 |
| 交易员 / 机器人（Trader / Bot） | 真正决定“这个策略信号要不要下单、下多少”的执行单元。 |
| 影子模式（Shadow） | 只记账、不真下单。用来验证交易员逻辑。 |
| 沙盒账户（Sandbox） | 用虚拟资金模拟买卖的账户，和真钱完全隔离。 |
| 实盘（Live） | 真钱、真下单。需要私钥、授权、风控。 |
| 敞口（Exposure） | 当前押了多少钱在市场里。 |
| ROI | 回报率，利润 ÷ 成本。 |
| 回测（Backtest） | 用历史数据重放一遍，看策略过去会不会赚钱。 |
| 数据集（Dataset） | 回测/Data Lab 里已经导入或录制好的一段历史数据；带 `PARQUET` 的才是回测可直接用的。 |

补充两个运维词：

- **worker**：后台常驻任务，比如扫描器、发现、对账、兑付。
- **plane**：一组 worker 的进程分组，例如 trading、detection、news。

## 3. 打开系统并确认它真的在运行

### 3.1 第一次打开

1. 在 Finder 里打开项目目录：
   `/Users/ahs/Projects/homerun`
2. 进入 `scripts → launchers`。
3. 双击 `Homerun.command`。
4. 等它自己启动。正常会打开浏览器，地址是：
   `http://127.0.0.1:3000`
5. 如果浏览器没有自动弹出，手动打开浏览器，输入上面的地址。

第一次打开如果页面空白，等 5～10 秒。后端要加载市场缓存，空白几秒是正常的。

> 如果启动器窗口出现 `ModuleNotFoundError: No module named '_tkinter'`，**不用管**。这只影响桌面小窗口，不影响网页。启动器现在会自动回退到能用的 Python，找不到就直接打开浏览器。

### 3.2 日常启动和“重启”

- **系统已经在跑**：直接打开 `http://127.0.0.1:3000`，不用再双击启动器。
- **页面打不开，或状态点变红**：先关闭浏览器页面，再双击一次 `Homerun.command`，等 30～60 秒，重新打开网页。
- **不要反复双击启动器**：它不会杀掉已经在运行的服务；反复点只会重复打开窗口。
- **不要用任务管理器/活动监视器强杀进程**：会打断正在写的账本。先点网页右上角的 `Pause` 暂停，再重启。

### 3.3 网页里的健康检查：右上角状态点

这是本教程唯一推荐的“体检入口”，不需要看接口。

1. 看网页**右上角**，`Pause` 左边有一个带圆点的 `Worker and VPN status` 按钮。
2. 把鼠标停在按钮上，会弹出 `Worker 健康` 面板。
3. 面板里会列出 11 个 worker：扫描器、扫描器 SLO、发现、天气、新闻、加密、已追踪交易员、调度器、对账、兑付器、事件。
4. 每个 worker 前面有一个小圆点：
   - 绿色 = 正常；
   - 琥珀色 = 警告/设计内暂停；
   - 红色 = 有问题。

顶部状态条还会显示 `推送连接 / 已连接`。它说的是网页与后端的**实时推送连接**，不是“系统在线/离线”。看到 `推送连接 已断开` 只表示推送断了，页面仍可能正常显示；先刷新页面，不要据此判断整个系统挂了。

**当前正常基线（2026-11-12 实测，数字会随扫描变化）：**

- 顶部状态条显示 `工作器 10/11 · 1 警告`；
- 悬停面板显示 `10/11 green`；
- 那 1 个琥珀色是 `新闻`，因为它被主动关掉省钱（`enabled=false`），但 `news` 进程本身仍在跑；
- 其余 10 个是绿色；`天气` 在跑，最近一轮有更新；
- 策略页当前是 **29 个已加载策略**，不是 30 个：少的那一个是主动停用的 `cross_platform`。

> 不要为了把 `10/11` 凑成 `11/11` 去打开新闻。新闻会调用 LLM，打开就会产生费用。

### 3.4 顶部状态条怎么读

顶部不是装饰，它是快速体检。**具体数字每轮都会变，不要拿一个固定值当“正常”。**

| 字段 | 含义 |
| --- | --- |
| `工作器 10/11 · 1 警告` | 10 个绿色 + 1 个琥珀（新闻设计内关闭）。不是 worker 崩了。 |
| 市场数量 | 当前扫描到的市场数量，会随扫描轮次变化；重启后短暂变化也正常。 |
| 交易员数量 | 交易员/机器人数量，可能随启停变化；以页面实际显示为准。 |
| `新闻` / `天气` | 对应模块的机会/意图数量；新闻关闭时这个数字可能来自历史。 |
| `信号 P:S:X` | 当前扫描器产出的信号数；`S` 和 `X` 是跳过/失败计数。 |
| `策略 29` | 当前已加载策略数量；`cross_platform` 停用后是 29，不是 30。 |
| `漏斗` | 扫描量到机会的漏斗；0% 不一定异常，要看机会页是否有数据。 |
| `事件 ...` | 最近 1 分钟的事件摄取计数，用于判断数据源是否还在动。 |
| `挂单 0` | 实盘编排器的挂单口径；沙盒持仓不计入。 |

### 3.5 页面空白/地图空白怎么办

- 页面整体空白：等 5～10 秒；仍空白就刷新一次 `Cmd+R`。
- 数据页“地图”首屏空白 3～4 秒：正常，等瓦片加载。
- 地图一直空白：先切到别的标签再切回来；仍不行就强刷新 `Cmd+Shift+R`。
- 地图 2026-11-10 的 3 条 `422` 已修复；如果再次出现，先强刷新，仍出现就找维护者，不要自己改参数。

## 4. 界面地图：10 个标签分别干什么

顶部导航从左到右是：

| 标签 | 作用 | 新手要不要马上用 |
| --- | --- | --- |
| 机会 | 看系统扫出来的套利/错价机会 | 要，先看这里 |
| 机器人 | 查看/配置/启停交易员；顶部有 Cortex 抽屉；当前未发现“新建机器人”入口 | 要，决定谁去下单 |
| 持仓 | 查看沙盒/实盘当前持仓 | 要 |
| 业绩 | 看盈亏、ROI、胜率、回撤 | 要 |
| 账户 | 沙盒交易台、实盘交易台、账户总览 | 要，先建沙盒账户 |
| 策略 | 策略列表、源码、研究、回测、验证 | 后面用 |
| 交易员 | 发现、池、已追踪、分析、图表、管理 | 进阶用 |
| 数据 | 地图、事件、新闻、来源；Data Lab 四模式 | 进阶用 |
| AI | AI 聊天、判定、研究工具 | 可选 |
| 设置 | 语言、主题、通知、API、高级参数 | 要，至少改语言 |

机会页还有 7 个子标签：**市场、交易员、新闻、天气、加密货币、体育、搜索**。
右上角可以切换三种视图：**卡片 / 列表 / 终端**。三个视图按钮在窄窗口（842 像素）下已经自动换行，全部可见可点。
注意：这三个视图是“看机会”的方式；真正下单入口在 `机会 → 交易员` 卡片底部的 `买入`，不是每张市场卡片上都有。

**Cortex 在哪里？** 在 `机器人` 页顶部右侧的 `Cortex` 按钮，点开是抽屉，里面有三个页签：`活动 / 记忆 / 设置`。详见第 9.2 节。

### 4.1 设置页常用分组

设置页里可以改的内容，按新手使用顺序：

| 分组 | 作用 | 新手建议 |
| --- | --- | --- |
| 语言 / 外观 | 界面语言、浅色/深色/跟随系统 | 先改成简体中文和深色，减少误读 |
| 搜索 | Polymarket 平台开关、每页结果数量 | 默认即可；数量越大越吃内存 |
| 扫描器 | 扫描间隔、机会阈值、池容量 | 不要为了“更快”把间隔调到 5 秒，会触发限流 |
| 通知 | Telegram 提醒 | 可选，不配也能用 |
| 界面锁定 | 本地屏幕锁、闲置超时 | 单人本机可不配 |
| 交易 VPN/代理 | 交易请求走代理 | 只影响交易链路，不影响浏览器刷新 |
| 网络访问 | 允许局域网设备访问面板 | 默认仅本机；开之前先确认网络环境 |
| 发现 | 钱包发现的增长与维护 | 默认即可，改大后更耗 RPC/内存 |
| 数据提供商 | Polybacktest API Key、逆向工程默认值 | 回测要导入数据集时才需要 |
| 数据库 | 清理与维护 | 不要随手点清理，先看提示 |
| 导入 / 导出 | 迁移交易配置包 | 改配置前先导出备份 |
| 区块链 RPC | 钱包监控的 Polygon RPC | 公共层级有速率限制，长期跑建议填自己的 RPC |

> 设置页的分组展开本身不会保存；每个分组里要单独点 `保存`。上线前不要把“能展开”当成“已配置”。

## 5. 第一次上手：30 分钟走完一遍

### 第 1 步：确认账户

打开 `账户` 标签，看顶部账户选择器：

- 如果显示“未选择账户”，点开下拉，选择一个沙盒账户；
- 如果没有沙盒账户，点 `沙盒交易台`，再点操作行里的 `新建`。

### 第 2 步：创建一个沙盒账户

路径：**账户 → 沙盒交易台 → 主内容操作行的 `新建`**。

> 窄窗口（约 842 像素）下，左侧 `沙盒舰队` 会被隐藏；不要去找左侧的 `新建`，用右侧操作行里的 `新建` 即可。弹窗标题是 `新建沙盒账户`。

填写：

| 字段 | 允许范围 | 建议值 |
| --- | --- | --- |
| 账户名称 | 必填，最长 100 字符 | `沙盒测试1`（或你自己的名字） |
| 初始资金（USD） | 100 – 10,000,000 | 10000 |
| 单仓上限（%） | 1% – 100% | 10 |
| 最大持仓数 | 1 – 100 的整数 | 10 |

点 `创建`。创建后你会看到：

- 模拟资产约 $10,000；
- 模拟盈亏 $0；
- 模拟持仓 0。

当前已有一个示例账户：`沙盒测试1`，资金、盈亏、持仓和胜率都会随交易变化。你可以直接用它练手，也可以新建一个；**不要拿教程里的历史数字去对账。**

### 第 3 步：看机会

打开 `机会` 标签，默认在 `市场` 子标签。

你会看到一张张机会卡片，重点看：

- 标题：哪个市场；
- 策略：哪个策略发现的；
- 成本 / 预期回报 / ROI；
- 风险分。

如果卡片太多，用顶部搜索框或筛选器；也可以点右上角 `Refresh` 手动刷新一轮。

### 第 4 步：准备一个“影子”机器人

新手不建议自己从零配置交易员。`机器人` 页会显示当前运行中的机器人数量（以页面实际显示为准），可直接用已有的影子机器人：

1. 打开 `机器人` 标签；
2. 在机器人列表里找到 `沙盒测试机器人1` 或 `新闻机器人 1`；
3. 看它的模式标签，必须是 `影子`（Shadow/`SHADOW`），不能是 `实盘`；
4. 记住它的名字，买入时要在 `执行方` 里选它。

**当前网页没有“新建机器人”入口**：机器人页顶部只有 `Cortex`、`设置` 和启停控制，没有 `+` 或 `创建第一个机器人`。不要为了新建去找接口或代码；用已有影子机器人即可。

> 不要为了“试试实盘”把模式改成实盘。当前没有实盘凭证，实盘买入会失败；即使以后配好，也会动真钱。

### 第 5 步：确认策略已加载

路径：**策略 → 策略**

找到你要用的策略（例如 `basic`、`stat_arb`、`weather_distribution`），确认：

- 状态是 `loaded`；
- 开关是启用；
- 没有红色错误信息。

新手不需要改策略源码。看到 `loaded` 就行。

### 第 6 步：等第一轮扫描

- 顶部扫描器状态在动；
- 子标签计数逐步出现。

如果一直是 0，先看第 11 节“常见故障”，不要反复点 `Refresh`。

## 6. 日常使用：看机会、买入、看持仓、看业绩

### 6.1 看机会的三种视图

| 视图 | 适合谁 | 买入入口在哪里 |
| --- | --- | --- |
| 卡片 | 快速浏览 | 市场卡片本身只有 `分析`；下单去 `交易员` 子标签 |
| 列表 | 对比多个机会 | 同上 |
| 终端 | 看深度、扫信号 | 同上 |

**真正能下单的入口是：`机会 → 交易员` → 卡片底部 `买入`。**
`机会 → 市场` 的卡片上通常只有 `分析` 和方向文字（例如 `BUY NO`），`BUY NO` 不是按钮，不要直接点文字。

### 6.2 网页里“买入”到底买了什么

这是最容易误解的一步，先看清楚：

- `机会 → 交易员` 的 `买入` 按钮，走的是**交易员手动买入**；
- 它不会直接改你选中的沙盒账户余额；
- 它会写入所选交易员的订单和持仓；
- 如果所选交易员是 `影子`，只记账，不花真钱；
- 如果所选交易员是 `实盘`，会走真实下单（当前未配置凭证，会失败）。

**操作步骤（2026-11-11 实测，不提交订单）：**

1. 打开 `机会`，点上方 `交易员` 子标签（不是 `市场`）；
2. 选一条有 `买入` 的机会卡片，点 `买入`；
3. 弹出 `下单` 对话框，确认：
   - `订单类型`：新手选 `市价`；
   - `仓位大小`：点 `$ 10`；
   - `执行方`：选 `沙盒测试机器人1 影子`（不要选 `新闻机器人 1`）；
4. 看 `交易摘要`：成本 `$10`、入场价、股数 `~18.7`、若 Yes 的收益；
5. 此时底部按钮会变成 `买入 $10`。**确认它只进入影子账本后，再决定是否点击提交。**
6. 如果提交，看到 `订单已下达` 后点 `完成`；
7. 想核对就去 `机器人` 页点 `前往交易者`，或去 `持仓` 页看。

> 教程实测只做到“看到 `买入 $10`”，**没有点提交**。所以你第一次实操时，先确认 `执行方` 是影子机器人，再点。`新闻机器人 1` 也是影子，但为了不混淆，建议统一选 `沙盒测试机器人1`。

如果 `执行方` 下拉里显示 `没有可用的已启用机器人`，说明当前没有启用的机器人；回到第 5 节第 4 步，先启用一个影子机器人。

### 6.3 看持仓

路径：**持仓**

- 顶部可切换 `全部 / 沙盒 / 实盘`；
- 可以按账户、场所、方向、规模筛选；
- 每行显示市场、链、方向、敞口、均价、标价、未实现盈亏、优势、信心、订单、模式、机器人、更新时间。

如果筛选后没有数据，会显示 `没有持仓符合当前筛选条件。`，点 `清除筛选` 恢复。

> 刚切到持仓页如果显示 `0 / 0`，先等 1～2 秒；数据是异步加载的，不要立刻判断没有持仓。

注意：顶部滚动条的 `敞口` 是**实盘编排器**的口径，不包含沙盒持仓。所以会出现“持仓 5 条、敞口 $0.00”，这不是数据错误，是口径不同。

### 6.4 看业绩

路径：**业绩**

顶部先选模式：

- `实时`：实盘/实时口径；
- `沙盒`：模拟账本。

**当前默认会跟随账户选择：选中沙盒账户时默认 `沙盒`，选中实盘账户时默认 `实时`。** 如果你当前是沙盒账户，打开业绩页第一眼就应该看到沙盒数据，而不是 0。

> 刚切到业绩页如果显示 `沙盒 • 0 笔交易`，先等 1～3 秒；数据是异步加载的。2026-11-11 实测约 3.5 秒后才出现交易记录；后续数字会变，不要立刻认为账本空了。

再选时间：`7日 / 30日 / 90日 / 全部`。

三个子标签：

- `概览`：已实现盈亏、`投入资本 ROI`、胜率、回撤；
- `洞察`：最佳/最差交易、ROI 中位数、策略表现；
- `历史`：逐笔交易。

新手只看两个数：

- **已实现盈亏**：已经结算的赚亏；
- **投入资本 ROI**：已实现盈亏 ÷ 买入成本，不是“账户总资产回报率”。

> 2026-11-11 的示例沙盒曾经显示过 `4 笔交易`、正收益、`投入资本 ROI +550.1%`、胜率 `100.0%`；这些只是当时的样本，当前数字一定不同。同一个页面的顶部 `账户 ROI`（宽屏才显示）是账户权益口径，和 `投入资本 ROI` 不是一回事，不要混算。

### 6.5 三个容易被吓到的数字（现在都有解释）

**1. 机器人概览的 `已验证已结算 P&L` 是 $0.00，但下面又写 `另有 2 笔未验证：+$9.54`**

这不是算错。当前系统把 P&L 分成两类：

- **已验证**：有市场结算结果、能和链上/ venue 对上的，才计入 `已验证已结算 P&L`；
- **未验证**：只有本地影子记录（`local`）、还没有外部结算凭证的，单独列在琥珀色一行。

交易行里的 `R-P&L +$4.8` 旁边会带一个 `未验证` 小标签。**看到 `未验证` 就不要把它当成已到账的钱。**

**2. 交易员发现页有的钱包 ROI 是 `—`，有的 ROI 带“估算”提示**

钱包 ROI 的公式没有变，仍是 `总盈亏 ÷ 总投入成本`。变的是成本基数从哪来：

- **精确**：上游给了买入成本，直接算；
- **估算**：上游没给成本，但给了“已平仓百分比”，系统用 `已实现盈亏 ÷ 百分比` 反推成本。这种 ROI 可以复核，但不是成交明细级精确，鼠标悬停会提示“由上游已平仓百分比反推，属于可复核估算”；
- **不可用**：成本基数缺得太多，或者算出来的值超过 ±1000%、明显不可能，就显示 `—`，鼠标悬停提示“成本基数不完整，ROI 暂不可用”。系统不会用 0 或一个离谱的百分比糊过去。

2026-11-11 实测：`VenomSuShi` 显示 `+734.2%` 并带估算提示；`justdance` 显示 `+123.2%` 并带估算提示；`@05001911` 显示 `—` 并带不可用提示。旧数据里成本基数正常的钱包仍照常显示，例如 `+372.0%`。

> 看到“估算”不要当成审计级真实成本。要精确到每一笔成交，仍以成交明细为准；页面上的提示就是提醒你这一点。

**3. 策略源代码第一行是 `# SEED TEMPLATE`**

说明你看到的是**策略模板源码**，不是正在运行的策略。代码上方会有一条琥珀色提示：`这是策略模板源码，不是当前运行时策略`。不要照着模板改参数就以为线上生效了。

## 7. 沙盒账户完整实操（网页版）

> 这一节全部是虚拟资金，不会动真钱。
> 当前沙盒是**即时成交**模型：下单即持仓，不产生挂单，所以没有撤单。

### 7.1 新建沙盒账户

1. 打开 `账户` 标签；
2. 点 `沙盒交易台`；
3. 点主内容操作行里的 `新建`（不要找左侧 `沙盒舰队` 里的按钮；窄窗口下左侧栏是隐藏的）；
4. 在弹窗 `新建沙盒账户` 里填写：
   - `账户名称`：`沙盒测试1`；
   - `初始资金（USD）`：`10000`；
   - `单仓上限（%）`：`10`；
   - `最大持仓数`：`10`；
5. 点 `创建`；
6. 看到 `模拟资产 $10,000`、`模拟盈亏 $0`、`模拟持仓 0` 即成功。

如果点创建后出现红字，按提示改：

| 红字 | 怎么改 |
| --- | --- |
| `请填写账户名称` | 名称不能为空。 |
| `初始资金需在 100 – 10,000,000 之间` | 改成 100 到 1000 万之间。 |
| `单仓上限需在 1% – 100% 之间` | 改成 1 到 100。 |
| `最大持仓数需为 1 – 100 的整数` | 改成 1 到 100 的整数。 |
| `创建失败，请检查后端服务后重试` | 先刷新页面；仍失败就找维护者，不要连续点。 |

### 7.2 查看沙盒账户的资产、持仓、交易日志

1. `账户 → 沙盒交易台`；
2. 在左侧 `沙盒舰队` 里点你的账户，或点 `打开`；
3. 右侧交易台默认在 `概览`，可以看到：
   - `模拟资产`；
   - `模拟盈亏`；
   - `模拟回报率`；
   - `模拟持仓`；
   - `未平仓位`、`交易台盈亏`、`可部署现金`。
4. 切到 `持仓`：看当前未平仓位；
5. 切到 `交易日志`：看逐笔成交；
6. 右上角 `刷新交易台` 可以手动刷新。

> 沙盒交易台当前没有 `订单` 子标签，也没有“手动结算”按钮。不要为了找订单去点别的页面。

2026-11-10 的示例账户 `沙盒测试1` 曾显示过资金约 `$9,991.61`、盈亏 `+$8.29`、5 个未平仓、4 笔交易、25% 胜率。你的数字会随交易变化，**不要拿历史示例当当前账本**。

### 7.3 在网页里“下单”：走交易员影子买入

**重要：直接对沙盒账户下单，网页当前没有按钮。**

网页里能做的“买入”是交易员手动买入，路径如下：

1. 确认有一个**已启用、模式为影子**的机器人（见第 5 节第 4 步）；
2. 打开 `机会 → 交易员`（不是 `市场`）；
3. 选一条有 `买入` 的机会卡片，点 `买入`；
4. `订单类型` 选 `市价`；
5. `仓位大小` 点 `$ 10`；
6. `执行方` 选 `沙盒测试机器人1 影子`；
7. 看到底部按钮变成 `买入 $10`；确认后才会提交。

这笔单会记在**交易员的影子账本**里，不会直接改 `账户 → 沙盒交易台` 里那个沙盒账户的余额。这是当前设计，不是 bug。

### 7.4 为什么沙盒账户余额没变

因为第 7.3 节的买入走的是交易员，不是沙盒账户。

- 想看交易员这笔单：`机器人 → 前往交易者`，或 `持仓 → 机器人` 列；
- 想看沙盒账户本身的资产：`账户 → 沙盒交易台`；
- 两者是两套账，不要用一边的数字去核对另一边。

### 7.5 结算和撤单

- **没有“手动结算”按钮。** 沙盒账本按市场结果和后台流程更新；网页里不要找“结算/开奖”入口。
- **没有“撤单”按钮。** 沙盒即时成交，下单后直接是持仓；想“反悔”只能等结算，或新建账户重来。
- 如果某笔持仓长期不变，先看 `业绩` 里是否已结算；仍不对就找维护者核对后台对账，不要自己用代码改账。

### 7.6 删除/重建账户

当前网页的沙盒交易台以查看为主；如果没有明显的 `删除账户` 按钮，不要强行找。可以新建一个账户练手，旧账户保留不影响使用。

## 8. 回测怎么用（网页版，含避坑）

### 8.1 界面入口

路径：**策略 → 研究 → 回测工作室**

进入后：

- 顶部有策略选择器，显示 `选择策略...`；先选一个策略；
- 左侧是 `设置 / 参数 / 运行`；
- 中间是结果区；
- 右侧是微观结构/成交模型信息。

### 8.2 关键避坑：不要用 `Auto` 当默认

**现象：** 点了运行，状态一直 `Queued` 或 `running`，进度 0%，`snapshots` 一直是 0，看起来像卡死。

**原因：**

- `Auto` 只给一个滚动时间窗口，没有明确数据集；
- 后端会去读全量历史 parquet，数据量太大，容易空转；
- 进度就会一直是 0。

**正确做法：在 `DATA SOURCE` 里选 `Datasets`，勾选一个带 `PARQUET` 的明确数据集。**

### 8.3 已真实点通的一条回测

1. `策略 → 研究`；
2. 顶部 `选择策略...` 选 `basic`；
3. 左侧 `设置`，`DATA SOURCE` 选 `Datasets`；
4. 勾选数据集：`BTC Up/Down · 5m · 2026-11-08 03:05 UTC (settled UP)`（约 `4,164 snaps`、`2 tokens`）；
5. 点底部 `Continue to Run`；
6. 点 `运行回测`；
7. 等状态变成完成；实测约 `2.0s`、`4146` 快照。

这条数据集的 ID 是 `polybacktest:f662df0204314654`，窗口是 `2026-11-08T03:06:13Z → 2026-11-08T03:09:59Z`。

这不是“只能用 10 分钟”的意思，而是**这条数据集本身就是 4164 个快照的明确范围**。选更大的数据集也可以，但要观察内存和耗时，不要回到 `Auto` 全量扫描。

### 8.4 怎么看结果

| 结果 | 含义 |
| --- | --- |
| `completed` / `ok` + `snapshots > 0` | 回测正常 |
| `completed` / `ok` + `trades = 0` | 正常，策略在该数据集没触发；**不等于故障** |
| `snapshots = 0` | 真的没读到数据，检查数据集是否选对 |
| 长时间 `Queued` | 后台任务没领到，或标签页在后台；见 8.5 |
| 长时间 `running` 且 0% | 回到了 Auto/全量扫描，或数据量超出内存包线；取消并改用 Datasets |

### 8.5 如果界面长时间停在 `Queued`

已知前端后台轮询在标签页失焦时曾停住。现在已加后台轮询，正常不会再长期停在 `Queued`。

如果仍遇到：**刷新页面即可自愈**。待运行的 run id 存在浏览器本地，刷新后会自动恢复，不会生成重复任务。

### 8.6 找不到数据集怎么办

1. 打开 `数据 → Datasets（数据集）`；
2. 进入 `提供者` 模式；
3. 点 `刷新`；
4. 如果列表为空，看设置页 `数据提供商` 里 Polybacktest API Key 是否已配置；
5. 配好后再回来 `Datasets` 勾选。

不要在回测页里反复点 `Auto` 试图“刷出来”。

### 8.7 导出 PDF 报告（当前不可用）

回测页有下载按钮，但本机当前缺少 `libpango`，点导出会返回错误/失败。**这是可选功能，不影响回测结果。**

不要为了 PDF 去安装系统依赖；先把回测结果看完。要用 PDF 时找维护者处理。

### 8.8 逆向工程（策略 → 研究 → 逆向工程）

这是“把一个已有策略/钱包反向拆开看”的功能，适合研究，不适合小白直接改生产策略。

- 打开后左侧是任务列表，右侧是结果；
- 当前默认选列表里最新一条任务（2026-11-11 实测为 `failed` 的 `re-1794356861744-9ab14126`），不会再默认跳到旧 `cancelled` 任务；
- `报告` 模式产出可读的 PDF；`功能`/`深度` 模式产出更细的源码分析；
- 任务状态 `failed` 不一定是功能坏了，可能是输入数据不足或模型没有返回结构；先看任务详情里的错误说明。

**不要**在逆向工程里点“应用到生产策略”或类似按钮。它只用于研究。

### 9.4 恢复/确认天气（不产生 LLM 费用）

**第 0 步：清掉残留的新闻扫描请求**

1. 点网页右上角 `Pause`（暂停全部）；
2. 等 3～5 秒；
3. 点同一个按钮，变成 `Resume`（恢复全部）。

- 天气一轮实测约 2～3 分钟（首轮 135.19 秒、第二轮 176.3 秒）。不要频繁点 `刷新`。

## 10. 风控与紧急停止

### 10.1 先认识三类开关

| 开关 | 在哪里 | 作用 | 是否跨重启保持 |
| --- | --- | --- | --- |
| `Pause` / `Resume` | 网页右上角 | 暂停/恢复全部 worker：交易、扫描、LLM 调用、数据摄取 | 否；`Resume` 会全部恢复 |
| Kill Switch（红色盾牌） | `机器人` 页顶部控制条 | 阻止所有新开仓；已有仓位管理（平仓与风控检查）继续 | 由编排器配置决定 |
| 机器人停止/启动 | `机器人` 页机器人卡片/控制条 | 停/启某个交易员 | 由机器人配置决定 |

**不要把 `Pause` 当成永久停用。** 它只是临时暂停，点 `Resume` 会全部恢复。要长期关某个子系统，当前网页只有部分模块有开关；没有开关的找维护者，不要反复点。

### 10.2 全局暂停/恢复（最常用）

1. 看网页右上角，`Pause` 按钮在状态点旁边；
2. 点 `Pause`：按钮变绿 `Resume`，顶部状态条显示 `已暂停`；
3. 点 `Resume`：恢复正常。

全局暂停期间，单独启动某个 worker 会被拒绝；这是设计，不是 bug。先 `Resume`，再单独操作。

### 10.3 机器人页的 Kill Switch

1. 打开 `机器人`；
2. 看顶部控制条，有一个红色盾牌图标的开关，旁边状态显示 `OPEN` 或 `BLOCKED`；
3. 打开开关：状态变 `BLOCKED`，所有新开仓被阻止；
4. 关闭开关：状态回 `OPEN`，恢复下单。

鼠标悬停开关会显示说明：**开启后立即停止所有新开仓，已有的仓位管理（平仓与风控检查）仍会继续。**

### 10.4 新手建议

- 始终让交易员处于 `影子`；
- 单笔金额不超过 $10；
- 不要打开 `实盘` 模式，除非私钥、授权、风控都配好；
- 每天看一次 `业绩` 和 `持仓`，确认没有异常单；
- 遇到不确定的情况，先点 `Pause`，再找维护者，不要连续点按钮。

## 14. 常见问题 FAQ

**Q1：为什么机会市场卡片上没有“买入”按钮？**
因为 `机会 → 市场` 的卡片只提供 `分析`；真正下单入口在 `机会 → 交易员` 的卡片底部 `买入`。`BUY NO` 是方向文字，不是按钮。旧版“市场卡片也有买入”的说法已过时。

**Q2：为什么我买了之后沙盒账户余额没变？**
因为 `买入` 走的是交易员手动买入，账记在交易员的影子账本里，不进 `账户 → 沙盒交易台` 的沙盒账户。要动沙盒账户本身，当前网页没有直接下单按钮，不要用代码去补。

**Q3：为什么持仓有 5 条，顶部敞口是 $0.00？**
顶部敞口取实盘编排器口径，沙盒持仓不计入。不是数据错误。

**Q4：为什么回测一直不动？**
先看你选的数据源。`Auto` 会落到全量历史 parquet，可能一直 0%；改用 `Datasets` 并勾选明确数据集。不要只把窗口改短，窗口短但仍是 Auto 也可能空转。

**Q5：为什么回测成功了却显示 `ok`，不是 `completed`？**
当前成功任务可能写 `ok`，两者都是终态。网页里看到完成/有快照就是成功。

**Q6：为什么新闻是停的？**
操作者要求暂不支付 LLM 费用，主动把新闻主开关设为关闭。新闻进程本身可以随 plane 运行，只是空转、不扫描；这不影响天气。

**Q7：为什么天气 `running` 但数据不更新？**
先看天气面板顶部 `最后...` 时间，再点 `刷新` 等 2～3 分钟；`running` 只是控制/心跳字段，不等于刚刚跑过。若长期不动，按 9.4 检查。

**Q8：能不能直接做实盘？**
当前不能。缺 Polymarket 私钥，实盘服务未初始化。配置完整凭证后还要先做最小金额验证。

**Q9：数据会不会丢？**
数据库有每日备份、日志轮转；但沙盒账户是测试账本，不建议存重要数据。

**Q10：Cortex 到底启用了没有？免费吗？**
当前未启用。Cortex 是可选 AI 交易运营代理；软件本身不额外收费，但它调用的 AI 模型可能产生费用。当前关闭，默认不花钱。

**Q11：为什么没有“撤单/结算”按钮？**
沙盒是即时成交账本，没有挂单，所以没有撤单；结算由后台按市场结果处理，网页没有手动结算入口。这是设计，不是缺按钮。

**Q12：这个教程里的操作真的不用命令吗？**
正文全部是网页点击。只有网页彻底打不开时，才需要在 Finder 里双击启动器；这也不是命令。

**Q13：为什么 Kalshi 没了、跨平台策略也不见了？**
当前上线口径是 **Polymarket 单平台**，`cross_platform` 已主动停用。这样不会每轮去请求不可达的 Kalshi、吃超时，也不会把“单平台”伪装成“双平台正常”。不是功能被误删。

**Q14：为什么策略数是 29，不是常说的 30？**
系统内置策略数量约 30 个；当前实际加载 29 个，少的那个就是停用的 `cross_platform`。以 `策略` 页的 `loaded` 列表为准。

**Q15：以后想恢复 Kalshi 怎么办？**
这是运维动作，不是小白在网页里点一下就行。必须先确认 Kalshi 出口可达、真实行情能拉通、跨平台机会能生成，再重新启用 `cross_platform` 并做一轮验收；不能只把开关打开。

**Q16：重启后机会变少，是不是又缩水了？**
正常不会。当前启动会从数据库快照恢复机会池，再按新一轮扫描合并；重启后短暂变化是正常的。如果持续只剩个位数，才按第 11 节找维护者。
