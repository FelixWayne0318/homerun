## 2. 修复设计（逐项）

### F1 账本口径统一（`backend/services/simulation.py`、`backend/api/routes_simulation.py`）

口径定义（写死，不再分支）：

- **成本基准 `entry_cost`**：该腿实际占用的现金，含分摊滑点。多腿按各腿 `price×size` 占比分摊，保证 `Σ entry_cost == trade.total_cost`。
- **市值 `market_value`**：`Σ quantity × current_price`（无 mark 时回落到 `entry_price`）。
- **未实现盈亏**：`market_value − Σ entry_cost`，实时计算，不信库里的历史列。
- **权益 `equity`**：`current_capital + market_value`。
- **ROI**：`(equity − initial_capital) / initial_capital`。
- **总盈亏**：`realized(account.total_pnl) + unrealized`。

改动点：

1. `execute_opportunity`：分摊滑点写进每腿 `entry_cost`；`current_price` 写成交价；`unrealized_pnl` 写 `−该腿滑点`；把生成的 `position_id` 回写进 `trade.positions_data`（为 `resolve_trade` 提供逐笔归属）。
2. `record_orchestrator_shadow_fill`：`entry_cost` 已含手续费，保持一致；`unrealized_pnl` 初始化为 `−手续费`（`quantity×entry_price − entry_cost`）。
3. `resolve_trade`：赔付改为 `Σ 获胜腿 quantity × 1.0`（二元市场每份结算 $1）；只结算**本笔成交**的持仓（按 `position_id` 精确定位，老数据回落 `opportunity_id`）；`payout` 不再用 `total_cost/腿数`。
4. `get_account_stats`：新增 `unrealized_pnl / book_value / market_value / equity`，ROI 改权益口径。
5. `/accounts`、`/equity-history`：同一套口径；净值曲线末尾补一个"当前权益"锚点，保证曲线终点 == `cash + market_value`。
6. `/positions`：`current_price` 空值回落 `entry_price`，`unrealized_pnl` 实时算。
7. 历史 3 笔成交做一次性对账回填（`entry_cost` 按 `trade.slippage` 分摊、`current_price=entry_price`），回填前 dump 原始行到 `data/backups/`。

不改：`POLYMARKET_FEE`、滑点模型、`close_orchestrator_shadow_fill` 的已实现盈亏公式（本就自洽）。

### F2 MCP 依赖上限（`backend/requirements.txt` + 环境）

## 3. 方案评估

### 3.1 风险与回归面

| 项 | 风险 | 控制 |
|---|---|---|
| F1 账本 | 高：改的是钱的口径，`entry_cost` 语义变化会改变 UI 展示与已实现盈亏 | 逐个消费方核对（仅 `routes_simulation` 读 `entry_cost`）；历史行先备份再回填；加三笔实测对账（`cash+market == initial+realized+unrealized`）；`resolve_trade` 只在手动端点使用，影响面可控 |
| F2 MCP | 中：降级 mcp 可能连带降压 `httpx/pydantic` | `pip check` + import 冒烟 + `/mcp` 实测；保留旧版本 wheel 回滚路径 |
| F3 类型 | 低：只加类型标注，不改运行逻辑 | `tsc` 归零 + `vite build` 通过 |
| F4 平面 | 中：news 2–3G、discovery 2G、detection 峰值 5G 叠加 16G 可能触发换页 | 分批启动并采样内存；必要时只保留 news+jobs，discovery 走按需 |
| F5 PG 自愈 | 中：脚本判断失误会误删有效 pid 文件 | 只在该 PID 存活且命令行不含 `postgres` 时改名；改名不删除；失败时 launchd 仍会退出，可人工恢复 |
| F6 提交 | 低 | 本地提交，不触碰远端；提交前 `git status` 全量核对 |

### 3.2 与设计意图的一致性

- 账本：`get_account_stats` 本来就返回 `unrealized_pnl`、`book_value`、`market_value` 三件套，说明设计意图就是"现金/成本/市值分离"，本次只是让三者互相自洽，没有新增概念。
- MCP：`http_app.py` 的注释明确写"FastMCP 的 streamable-http"，1.x 是设计选择；锁主版本即恢复原设计。
- 平面：`host.py` 的 plane 注释本身就是"进程隔离 + 常驻"，launchd 是这台机器既有的托管方式，补齐而非发明。
- 不做的：不自动创建 trader、不加净值快照表、不加撤销成交接口、不改前端接线率 —— 均属产品决策或新功能。
